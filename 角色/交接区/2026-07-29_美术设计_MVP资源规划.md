## 2. MVP 美术资源规划正文

### 2.1 MVP 美术风格方向

首版建议采用“高对比俯视符号化地牢”风格：

- 视角：2D 俯视，所有单位以顶部轮廓为主，不做复杂透视。
- 表现：低精度像素或扁平手绘均可，但 MVP 优先用几何剪影 + 强颜色区分。
- 基调：暗色地牢地面，亮色角色、弹体、道具，保证高速战斗中可读。
- 细节密度：低。背景不能抢过弹体、敌人和掉落物。
- 动画策略：玩家和普通敌最多 2-4 帧；Boss 可静态 + 呼吸缩放；弹体、道具、门优先静态。
- 资源优先级：正式贴图不足时，保留当前程序的圆形、矩形、菱形占位渲染也可以进入 MVP。

推荐颜色层级：

- 玩家：蓝色系，外轮廓浅蓝，受伤/无敌时变浅或闪白。
- 玩家弹体：黄色/暖白，尺寸小但亮度最高。
- 近战敌：红色系，圆形或尖角轮廓。
- 远程敌：紫色系，方形或长条枪管轮廓。
- Boss：洋红/粉紫色，尺寸显著大于普通敌。
- 敌方弹体：玫红/深红，必须和玩家弹体明显不同。
- 生命恢复：绿色。
- 射速/强化：青色。
- 出口门：关闭灰色，开启绿色。
- 地面/墙体：低饱和深灰，不使用高亮纹理。

### 2.2 当前技术约束与资源规格基准

当前程序状态：

- 技术栈：Python + pygame-ce。
- 运行入口：`python main.py`。
- 窗口尺寸：`1280x720`。
- 资源目录已存在：`assets/`，参数配置目录为 `assets/data/`。
- 当前尚无正式美术资源加载管线，实体直接在 `draw()` 中用 pygame 绘制圆形、矩形、多边形和文字。
- 玩法参数已进入 `assets/data/gameplay.json`，但颜色、窗口尺寸、占位渲染参数仍在 `game/settings.py`。

当前碰撞与显示半径：

- 玩家半径：18 px。
- 近战敌半径：24 px。
- 远程敌半径：22 px。
- Boss 半径：46 px。
- 玩家弹体半径：5 px。
- 敌方弹体半径：7 px。
- Boss 弹体半径：12 px。
- 奖励拾取半径：18 px。
- 门尺寸：44x104 px。

建议贴图规格以这些半径为基准，贴图视觉外轮廓可以略大，但透明边距不要影响程序碰撞理解。

### 2.4 资源识别要求

玩家：

- 必须和所有敌人反色或跨色系区分，首选蓝色。
- 瞄准方向必须清楚。MVP 可继续使用当前“瞄准线 + 端点”。
- 玩家主体不要和子弹一样亮，避免误读。

近战敌：

- 必须表达“会贴近碰撞”的威胁，建议圆形主体加尖刺、爪痕或红色外圈。
- 不要求攻击动画，接触伤害由位置和碰撞反馈表达。

远程敌：

- 必须和近战敌形状不同，建议方形/炮塔/竖直枪管。
- 即使没有旋转朝向，也要让玩家知道这是“射击单位”。

Boss：

- 必须大，不能只是换色普通敌。
- 允许基于放大敌人占位，但至少增加核心、外环或菱形剪影。
- Boss 血条必须比普通敌更醒目。

弹体：

- 玩家弹体和敌方弹体必须用完全不同色相。
- 敌方弹体优先清晰和危险，不追求华丽拖尾。
- Boss 弹体尺寸至少是普通敌弹 1.5 倍以上。

道具：

- 道具必须和弹体区分，建议统一用菱形底座 + 中央符号。
- 生命恢复与射速提升必须不用读文字也能区分。
- 道具上方文字可以保留，但不能作为唯一识别方式。

房间与障碍：

- 地面纹理低对比，不出现大量亮点。
- 墙和门只服务于通路理解，不做复杂装饰。
- 障碍物如果程序未接入碰撞，先不要在画面中使用实体障碍，以免误导玩家。

UI：

- MVP 可继续文字 HUD，但建议逐步替换为图标 + 数字。
- 信息优先级：生命 > 房间状态 > 冲刺冷却 > 武器/射速。
- 调试输入文字不属于正式 UI，应在 MVP 展示版中隐藏或降级为 debug 开关。

### 2.5 推荐尺寸、比例、朝向与动画

通用规格：

- 文件格式：PNG，透明背景。
- 命名：小写英文 + 下划线，按类型分目录。
- 坐标锚点：角色、弹体、道具全部以图片中心作为逻辑中心。
- 朝向：默认朝右。程序可通过旋转贴图适配瞄准方向；若暂不做旋转，保留现有线段瞄准。
- 像素密度：贴图尺寸建议为逻辑碰撞直径的 1.2-1.5 倍，留少量轮廓空间。

建议目录：

```text

assets/images/player/player_move_01.png
assets/images/player/player_move_02.png
assets/images/enemies/enemy_melee_idle.png
assets/images/enemies/enemy_ranged_idle.png
assets/images/enemies/boss_idle.png
assets/images/projectiles/projectile_player.png
assets/images/projectiles/projectile_enemy.png
assets/images/projectiles/projectile_boss.png
assets/images/items/item_heal.png
assets/images/items/item_fire_rate.png

assets/images/rooms/wall_edge.png

assets/images/rooms/door_open.png
assets/images/ui/icon_heart.png
assets/images/ui/icon_dash.png

```

动画帧建议：

- 玩家 idle：1 帧。
- 玩家 move：2 帧，可延后；没有动画时用静态图。
- 玩家 hit：不单独出帧，程序用闪白/换色。
- 玩家 dash：不单独出帧，程序用半透明残影或短线。
- 近战敌 move：1-2 帧。
- 远程敌 shoot：可延后，首版用开火瞬间闪烁即可。
- Boss idle：1 帧；程序保留当前呼吸缩放。
- Boss shoot：可延后，首版用发弹前短暂变亮即可。
- 道具：1 帧；可选程序上下浮动或描边闪烁。
- 门：关闭 1 帧、开启 1 帧；开门动画延后。

### 2.8 给程序开发的资源接入建议

1. 首轮接入不要一次替换全部绘制。建议先建一个轻量 `AssetManager`，只负责按路径加载 PNG、缓存 `pygame.Surface`、支持缺失资源时回退到当前占位绘制。
2. 资源接入顺序建议：弹体 -> 道具 -> 玩家 -> 敌人 -> Boss -> 门 -> UI 图标 -> 地面/墙体。
3. 继续保留 `draw()` 内的占位绘制作为 fallback，直到所有核心贴图稳定。
4. 贴图绘制中心应对齐当前实体 `position`，不要改变碰撞半径。
5. 若支持贴图旋转，优先只做玩家武器/瞄准方向和弹体旋转；敌人朝向可以延后。
6. UI 调试文本建议通过 debug 标记控制，正式 MVP 展示只保留生命、房间进度、冲刺、奖励提示。
7. 颜色常量暂时可以留在 `game/settings.py`；正式贴图稳定后，再决定是否迁移视觉配置。
8. 道具类型目前只有 `heal` 和 `fire_rate`，美术优先只交付这两类。
9. 当前房间无障碍物碰撞，先不要接入看起来可阻挡的障碍贴图。
10. 建议新增图片规格文档或在资源目录放 `README.md`，说明中心锚点、命名和推荐尺寸。

### 2.9 给音效音乐需要知道的视觉反馈信息

音效应与以下视觉反馈对齐：

- 玩家射击：玩家弹体为黄/暖白小亮点，音效应短、清脆，不要厚重。
- 玩家命中敌人：敌人会短暂变为橙/亮色，命中音效应轻短，避免和死亡音混淆。
- 玩家受伤：玩家会变浅/闪白并进入无敌帧，音效应有明确受击提示。
- 敌人死亡：敌人从画面移除；若没有死亡动画，音效需要承担“已击杀”的确认感。
- 远程敌开火：紫色敌方单位发射玫红弹体，音效应和玩家射击区分。
- Boss 开火：Boss 弹体更大，音效比普通敌方弹更低或更有压迫感。
- 道具拾取：道具为绿色/青色菱形，拾取后立刻消失并显示提示，音效应明亮、正反馈。
- 开门：出口由灰色变绿色，音效应短促明确，提示玩家可前进。
- 胜利/原型完成：半透明遮罩 + 大标题，音效可以短句式完成提示。
- 失败：半透明遮罩 + `DEFEAT`，音效应明显但不拖长。

### 2.10 免费素材或 AI 生成关键词

如果后续使用免费素材或生成图，建议关键词限制在低成本符号化方向：

- `top down pixel dungeon hero blue transparent png`
- `top down pixel dungeon enemy red transparent png`
- `top down turret enemy purple pixel art transparent`
- `top down dungeon boss crystal magenta transparent`
- `pixel art bullet projectile yellow transparent`
- `pixel art enemy projectile red orb transparent`
- `pixel art dungeon pickup heart green transparent`
- `pixel art speed boost pickup cyan lightning transparent`
- `dark dungeon floor tile low contrast pixel art`

AI 生成时必须指定：

- top-down view
- transparent background
- centered sprite
- readable silhouette
- no complex background
- low detail
- single object
- game sprite sheet only if animation is requested

## 3. 需要其他角色知道的信息

### 给程序开发

- 当前占位形状已经足够支撑 MVP 验证，正式美术接入不应阻塞音效埋点、调参和试玩。
- 美术建议以 PNG 贴图替换为渐进式任务，并保留当前 pygame 绘制作为 fallback。
- 请优先支持中心锚点贴图绘制、透明 PNG 加载、缺失资源回退。
- 暂不建议接入障碍物贴图，除非同步实现障碍碰撞和敌人/弹体处理。
- UI 的调试输入文字建议后续隐藏，否则会影响 MVP 观感。

### 给游戏策划

- 美术按当前已实现范围规划：`heal` 和 `fire_rate` 是 MVP 首批道具；伤害提升、最大生命提升暂列设计保留但延后出正式资源。
- 当前程序房间只有起始房、战斗房 1、战斗房 2、Boss 房；若目标仍是 6-8 房间，美术资源可以复用，不需要新增主题。
- 散弹枪尚未程序接入，美术不把散弹枪正式图列为 MVP 必须。

### 给音效音乐

- 视觉反馈首版会偏“形状 + 换色 + 文字”，音效需要承担一部分确认感，尤其是击杀、拾取、开门、失败/胜利。
- 敌我弹体颜色差异很强，音效也应区分玩家射击和敌方射击。
- Boss 当前是大体型、呼吸缩放、发射大弹体，音频可按“大而慢”的反馈设计。
