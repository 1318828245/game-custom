# 多终端角色协作流程

本项目没有真正的多 agent 系统时，可以用多个终端窗口模拟协作。每个终端窗口只扮演一个固定角色，通过 `角色/公共记忆.md`、`角色/任务看板.md` 和 `角色/交接区/` 交接信息。

## 推荐窗口分工

- 终端 1：游戏策划
- 终端 2：程序开发
- 终端 3：美术设计
- 终端 4：音效音乐

如果你只想开一个窗口，也可以按顺序切换角色，但每次切换前都要重新读取公共记忆。

## 每个窗口的启动提示

给某个终端窗口的第一句话可以使用：

```text
你现在扮演【角色名】。
请先阅读：
1. 角色/公共记忆.md
2. 角色/协作流程.md
3. 角色/【角色名】.md

之后只从该角色视角工作。每次输出都要说明：
1. 你完成了什么
2. 需要其他角色知道什么
3. 建议写入公共记忆什么
4. 是否需要更新任务看板
5. 已经写入哪个交接文件
```

## 自动汇总

角色窗口之间不需要互相复制输出。每个角色完成一轮工作后，只新增一个交接文件：

```text
角色/交接区/日期_角色名_任务名.md
```

主控窗口运行：

```bash
python tools/role_sync.py summary
```

脚本会把所有交接文件汇总到：

```text
角色/自动汇总.md
```

主控窗口只需要读取 `角色/自动汇总.md`，再决定如何更新公共记忆和任务看板。

## 交接归档

交接文件只用于“本轮尚未合并的信息”。主控窗口把内容合并到 `公共记忆.md` 和 `任务看板.md` 后，运行：

```bash
python tools/role_sync.py archive
```

脚本会把当前 `角色/交接区/` 下的交接文件移动到：

```text
角色/交接归档/时间戳/
```

建议规则：

- `交接区` 只保留当前未合并的文件。
- `公共记忆.md` 只保留长期有效的结论。
- `任务看板.md` 只保留当前阶段任务。
- `交接归档` 用于追溯历史，不作为日常读取内容。
- 每完成一个阶段，例如 MVP 设计完成、原型完成、第一次试玩完成，就归档一次。

## 标准工作循环

1. 读取 `角色/公共记忆.md`。
2. 读取 `角色/任务看板.md`。
3. 读取自己的角色提示词。
4. 认领一项任务。
5. 完成本轮工作。
6. 输出结论和交接信息。
7. 新增一个 `角色/交接区/` 下的交接文件。
8. 由主控窗口运行自动汇总并合并公共记忆、任务看板。

## 主控窗口

建议保留一个主控窗口，由你自己使用，不扮演具体角色，只负责：

- 决定下一步让哪个角色工作。
- 合并各角色对公共记忆的修改。
- 处理角色之间的冲突。
- 控制 MVP 范围。
- 决定是否进入开发实现。

主控窗口不需要一直存在，但在多窗口同时工作时很有用。

## 文件修改边界

- 游戏策划优先修改：需求、玩法、版本计划、MVP 范围。
- 程序开发优先修改：代码、技术方案、开发任务、运行测试说明。
- 美术设计优先修改：美术风格、资源清单、规格、生成提示词。
- 音效音乐优先修改：音频清单、触发规则、音乐风格、素材关键词。
- 公共记忆和任务看板建议由主控窗口合并，避免多个窗口同时覆盖。
- 普通角色窗口默认只新增 `角色/交接区/` 下的文件，不直接修改公共记忆和任务看板。

## 冲突处理

- 玩法体验和开发成本冲突时，保留核心体验，缩小表现和内容量。
- 美术表现和识别清晰度冲突时，优先识别清晰度。
- 音效丰富度和信息清晰度冲突时，优先信息清晰度。
- 任何角色发现范围过大，都可以要求缩减 MVP。

## 推荐开发顺序

1. 游戏策划输出 MVP 设计。
2. 程序开发评估技术可行性和开发任务。
3. 美术设计输出 MVP 资源清单。
4. 音效音乐输出 MVP 音频清单。
5. 主控窗口合并公共记忆。
6. 程序开发实现第一版原型。
7. 试玩后四个角色按问题迭代。
